# Bounded Orphan Stage Verification

## Status

Accepted.

## Context

Hot maintenance planning stopped parsing projection-work raw, but still hashed
every abandoned staged raw copy while classifying cleanup. On the live archive
those generated stages cover tens of gigabytes, so a routine status or cleanup
recommendation could take minutes and preempt semantic search and graph work.

## Options Considered

- Keep hashing every stage in hot status. Rejected because status latency would
  continue to grow with abandoned generated bytes.
- Delete PID-dead stages from metadata alone. Rejected because PID absence does
  not prove that stronger raw authority exists.
- Inventory stages from metadata in hot status and move exact raw-authority
  proof into a bounded explicit cleanup cycle. Accepted.

## Decision

Hot maintenance planning performs zero staged-raw authority checks and does not
let unverified cleanup debris preempt semantic maintenance. Explicit cleanup
verifies at most one exact stage candidate per apply cycle and skips unrelated
deep projection-work identity scans. The complete dry-run audit remains
available, and apply still repeats exact raw-authority proof before removing a
stage.

## Rationale

Generated debris is an operational storage concern, not evidence that current
search or graph projections are semantically stale. Separating its bounded
verification from hot routing keeps freshness work moving while preserving the
raw-evidence deletion boundary.

## Consequences

- Positive: hot status no longer reads staged raw proportional to archive size.
- Positive: cleanup can make bounded progress without an all-stage hash pass.
- Positive: orphan debris cannot starve search and graph catch-up.
- Tradeoff: complete debris classification remains an explicit deep audit, and
  several bounded cycles may be required to remove several proven-safe stages.

## Boundaries

This does not authorize deletion from PID, age, name, or size alone; weaken raw
authority comparison; delete legacy unowned stages; or claim that debris
cleanup is semantic freshness.

## Follow-Up Route

Let hot maintenance continue semantic catch-up. Run bounded stage cleanup as a
separate operational drip, and use the unbounded explicit audit only when an
operator actually needs complete debris classification.

## Verification

Use regressions that fail if hot planning reads staged raw, prove one apply
cycle checks only one candidate, retain explicit unresolved-authority failure,
then measure live hot status and one bounded cleanup cycle.
